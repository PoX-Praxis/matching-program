# 加入（コミュニティへの参加申請）の設計メモ（指示書45 A 群・45A 追補）

更新: 2026-09-26 ／ 実装: PR #110（A 群）

## 1. 加入トークの状態遷移

```
審議中 ──承認────────────────▶ 決定済み（既存の member.joined が記録を担う）
審議中 ──見送りの確定────────▶ 決定済み（通常DBのみ。台帳に書かない）
```

- 決定済みの後は**投稿と票は 409**（提議・プロジェクトと同じ規律）。
- **加入トークに休眠の語彙は出さない**。長く無活動でも「審議中」のまま、投稿も拒否しない（§4）。
- **`admission.rejected` を作らない。加入の見送りを台帳に書かない。**
- 決定後も**トークを削除しない**（メンバーには読める。第三者には 404）。
- 実装: `src/talks.py`（`decline_admission`・`can_decline_admission`・`is_closed`）、`POST /api/talks/<id>/decline`。

## 2. 表示語と、見送りの 2 種の区別

| | 判断の対象 | 可視性 | 表示 | 再申し出 |
|---|---|---|---|---|
| **コミュニティ加入の見送り** | 人そのものへの評価 | **メンバーのみ**（本人には本人面で結果のみ） | **見送り** | **可**（本人面に明示。実装は 45A 追補2） |
| **プロジェクト参加の見送り** | 目的と関わり方 | **公開** | **見送り** | **可** |

- 語は両方とも「見送り」。**扱いは別**（加入＝非公開・台帳に書かない／参加＝公開・再申し出可）。
- 「拒否」「不承認」「却下」は**表示に使わない**（D-4：却下されるのは案であり人ではない）。内部値は `talks.status='declined'`・`community_members.status='rejected'` で、画面・API の表示語には出さない。
- **恒久的に締め出さない**。再加入の可否は本人の意思と集団の状況で変わる（発注者の決定 2026-09-27）。

## 3. 要約（本人面で見せる理由）

- **見送りを確定するメンバーが任意で書く文。最大 280 字**（超過分は切り詰める）。
- **審議の内容・票・反対した人を書かない**（A-2 の趣旨を要約でも守る。画面の入力欄の説明にも明記）。
- 保存は**通常DBのみ**（`talks.result_json.summary`）。加入系と同じ `X-Robots-Tag: noindex, nofollow` の対象。

## 4. 見送りの確定権限と滞留

- **確定権限**: 分母のメンバーから**反対が出ているときに限り**、メンバーが確定できる（1 人の専断を防ぐ）。反対が無いときは 409。
- **壁時計で自動確定しない**。加入トークの状態遷移に時刻を入れない。
- **滞留は表示のみで気づく**（メンバー面・本人面の見せ方は後続）。
- **加入トークに休眠の語彙を出さない**（指示書49 追補と対）。
