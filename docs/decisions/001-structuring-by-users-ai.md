# 001 構造化は利用者の AI にさせ、サーバーは判断しない

- 日付: 2026-11-08（`docs/status-report.md` §7 から起こした日。決めた日は根拠の PR を見る）

- 決めた人: 未確認

## 決めたこと

- プロフィールの構造化と必要像・与え像の文は、利用者が自分の AI に作らせる
- サーバーは構造化のための LLM を呼ばない。受け取った JSON を検証して保存するだけにする
- プロンプトは `docs/prompts/` が唯一の正で、登録画面はそこから読み込む

## 理由

- ポリシーの事実（必要像を書くのは利用者の側）に合わせるため（指示書37 §1-2）
- プロンプトの立場は「判断しない採集者」（v4 の構造化プロンプト）
- 【推測】サーバーに、LLM の費用と生成した内容の責任を持たせないため

## 捨てた選択肢と理由

- **サーバー側で必要像を生成する経路（fallback B）:** 指示書28 段階5（PR #69）で廃止した
  - `app.py` の注記: 「必要像は①が必ず出す前提。無い入力は受理側で弾く」

## 影響範囲

- `templates/register.html`・`docs/prompts/`・`src/v5.py`・`src/profile_view.py`・`app.py`（`/v4/drafts`・`confirm`）
- **例外が残っている:** v3.1 → v4 の遅延移行（`src/migrate_v4.py` → `src/db_v4.py` の `ingest_profile_v4`）は、まだサーバー側で必要像を作る（`docs/status-report.md` §5-2）
