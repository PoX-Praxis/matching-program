## 決めたこと

- 照合のスコア・g・閾値は、画面と公開 API に出さない
- 照合の応答は、候補の id と「最も効いた軸」の名前だけにし、並びは id 順にする
- 数値は監査ルート（`/ledger/audit/match`）にだけ出す

## 理由

- スコアが順位や序列として読まれ、体験が「割り当て」になるのを避けるため（指示書55）

## 捨てた選択肢と理由
