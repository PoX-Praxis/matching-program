# 休眠（指示書49・49 追補）

更新: 2026-09-26 ／ 実装: PR #109（49 追補に合わせて対象を提議トークに限定）

1. **「最後の活動」の定義**: トークの作成・**発言の投稿**・**票の投下**のうち最も新しい時刻。票は賛成⇄反対の変更も投下として数える。**票を取り消す操作は存在しない**（API は `approve`／`dissent` のみ）ため、取り消しが活動に数わることもない。
2. **`talk_events` というテーブルは存在しない**。指示書49 §1-1 の文言と異なり、実装は `talk_posts.created_at`・`talk_votes.updated_at`・`talks.created_at` で導出している（推測の記録）。
3. **閾値 30 日は定数**（`talks.DORMANT_AFTER`）。**書き込み可否・可視性・合意判定に効かせない**（49 §2）。将来 挙動に効かせるなら Layer 1 の `declaration` 値にする（今回は行わない）。
4. **休眠の対象は審議中の提議トークのみ**。**加入トーク・参加・達成・プロジェクト・チャットには休眠を出さない**（加入トークの滞留は `docs/admission.md` §4）。
   - 注: PR #109 の初版は「締め切られていない決定トーク全般」を対象にしていた。49 追補・45A 追補 §1-4 の記録に合わせ、提議トークのみに狭めた（`talks.is_dormant`）。
5. **休眠は表示時に計算するだけで、台帳に書かない**。追記・票で**自動的に戻る**（再開操作を作らない）。**投稿を拒否しない**（拒否は合意済み・完了・加入の決定済みのみ）。**可視性を変えない**（休眠でも公開のまま、削除しない）。

時刻は `talks._clock()` から取り、休眠の表示と投稿・票の時刻にだけ使う。合意判定（`talks.evaluate_talk`）は時刻を参照しない。
