## 1. 前提（変わらない）

- 照合は nomic のまま。LLM は選ばれた相手について「つながる意味」を言葉にするだけ（段1：句の対応と R1〜R4、段2：① だけ）。確かめを通らないものは出さない
- **外部の AI（ChatGPT・API 等）を使わない。** 理由：利用者の文を外に出さない／版を固定して後から確かめられる／他社に依存しない
- 推論は **KAORU の個人 PC**（nomic と同じ）。説明は前もって作って DB に保存するので、常時稼働は要らない
- 基準テストは、全員の説明の質を決めるモデル選定の合否にだけ使う。**プロンプトの調整には使わない**（事前登録）

## 4. Code に頼むこと（調べものだけ。コードは変えない）

1. **前回のリソース不足の記録**：66C・69 で llm-jp を動かしたときに足りなかったのは、メモリか時間か。そのときの方式（transformers・fp32・CPU/GPU）と、かかった時間・使ったメモリ（記録があれば）
2. **nomic の動かし方の記録**（あれば）：KAORU の PC の性能・推論の方式・本番からのつなぎ方。無ければ「無い」と書く（KAORU が帰宅後に確かめる）
3. **候補の現物の確認**（Hugging Face の公式のページで）：
   - LLM-jp-4 8B と 32B-A3B の指示応答の版の正式なライセンス名と revision
   - Nemotron Nano 9B v2 Japanese のライセンスの版と、安全の仕組みに関する条項（外すと権利が失われるか）
   - 3 つの候補が llama.cpp（公式の版）で動くか。LLM-jp-4 は専用の fork が要るという報道がある（33B）。Nemotron（Mamba 混在）の対応状況
   - 各候補の GGUF の有無と、4bit・8bit のファイルの大きさ
