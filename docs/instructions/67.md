- 関わっている組（申し出中・承認待ち・接続中）の根拠の表示（65-B §1-3 の「要素で応える」）
- 下層の表示のフラグ `POX_LOWER_LAYER_OPEN`（閉じたまま）
- 数値を画面と公開 API に出さない

## 1. 上層の印の保留

### 1-1. 対象

上層の印（「欠かせない要素をすべて覆う人」と、それに類する見出し・文言）を出している箇所すべて。少なくとも次を確かめる。

- つながる（`/connect`）の目的ごとの表
- 相手のプロフィールの「あなたの必要から見た、この人」（65B-4・`/api/connections/preview`）
- `/v4/match` の応答（画面が使う欄）
- 登録者一覧のラベル（63 PR-E）があれば、それも

### 1-2. 振る舞い

- 新しい設定値 `POX_UPPER_BADGE_SCOPE` を足す。値は `all`（いまの振る舞い）／`related`（関わっている組だけ）。**既定は `related`**
- `related` のとき、関わっている組（申し出中・承認待ち・接続中）以外には、上層の印・見出し・「欠かせない要素をすべて覆う人」の文言を**出さない**
  - API の応答からも、その組以外では上層の成否の欄を外す（画面で隠すだけにしない）
- 関わっている組では、いまの表示のまま
- 上層が「成立しない」ことを示す文言（「目的のすべてを満たす照合ではなく…」など）も、関わっている組以外では出さない。出すと、印を出さないことの意味が読み取られてしまうため
- 欠かせない要素が無い目的の文言（「この目的には欠かせない要素がありません。補完の照合は行われません」）は、本人のマイページの説明として残す（照合の結果の表示ではないため）

### 1-3. 印を出さない間の、つながるの画面

- 上層の印が出ないと、関わっていない相手について、目的ごとの表に何も出なくなる場合がある。そのときの表示を報告する（空の表になるのか、相手がそもそも並ばないのか）
- **文言は足さない。** 「準備中」などの新しい文言が要る場合は、案を報告して止まる（KAORU が決める）

### 1-4. テスト

1. `related` のとき、関わっていない組で、上層の印・見出し・文言が画面にも API にも出ない
2. `related` のとき、申し出中・承認待ち・接続中の組では、いまと同じ表示が出る
3. `all` に戻すと、いまの振る舞いに戻る
4. 上層の計算は `related` でも行われ、監査のルート（`/ledger/audit/match` など、本人と監査だけ）では見える
5. 下層のフラグは閉じたまま

## 2. 本番のデプロイの確認

1. Render の pox-web で、いま本番に出ているコミット（短いハッシュとメッセージ）を報告する。Code から見えない場合は、KAORU に確かめる手順（Render の管理画面 → pox-web → Events）を示す
2. main の最新と、本番のコミットが一致しているか
3. 本番で次が見えるかを、手順として KAORU に示す（Code は本番のアカウントに触れない）
   - マイページ：目的ごとの必要像の文に「欠かせない要素／あれば嬉しい」の切り替え（65B-7）
   - 相手のプロフィール：「あなたの必要から見た、この人」の欄（65B-4）
   - 受信箱・つながるのカード：関わっている組の「要素で応える」の見出し（65-B §1-3。上層が通っていない組で出る）
4. 本指示書の PR をマージした後、もう一度 1 を確かめて報告する
