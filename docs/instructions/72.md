## 1. 物差しを2つにする

### 1-1. KAORU の 48 組（手元だけ）

- KAORU から渡す `labels_v1.json` を `local/65a/labels_v1.json` に置く（リポジトリに入れない）
- 各組に `final`（下層のラベル。65-A のまま）と、新しく **`expl_label`**（説明用のラベル）がある
  - `expl_label` は配列。`["R1"]`・`["R4","R1"]`（どれでも正しい）・`["説明できない"]`・`["判断できない"]`・`["対象外"]`
  - 下層のラベルから変えたもの：L08 → R2、L34 → R4、L40〜L42 → 対象外（本人どうし）
- 出どころは `final_source`・`expl_note` に書いてある

### 1-2. 架空の人の組（リポジトリに入れる）

- `explanation_bench_synthetic_v1.json`（架空の6人・必要12・組60）を `data/explanation_bench/synthetic_v1.json` に置く（実在の人の文を含まない）
- 形：`people`（目的・種類・必要と必須）と `pairs`（`need`・`other`・`expl_label`・`note`）
- 内訳：説明できる 28（R1 11・R2 8・R3 4・R4 10。重なりあり）・説明できない 25・判断できない 7

**理由:** 48 組はほぼ KAORU の必要だけでできている。選ぶモデルは全員の説明を作るので、物差しを一人の必要に寄せない。

## 2. 計測（`scripts/explanation_measure.py`）を物差しに合わせる

1. 組ごとに、**その組の必要と相手の文だけ**で説明を作る（1 つの必要 × 1 つの相手の文。KAORU の組は KAORU の必要、架空の組はその人の必要）
2. 数えるもの（物差しごと・合計）:
   - **誤り**：`説明できない` の組に説明を出した数
   - **拾えた**：`説明できる` の組に説明を出した数（＝出した数 ÷ 説明できるの数）
   - **関係の一致**：出した説明の R が `expl_label` に含まれる数
   - `判断できない`・`対象外` は数えない（件数だけ記録）
3. **1 回ごとの結果の種類を記録する**（文は記録しない）：
   (a) JSON として読めなかった (b) JSON は読めたが組が 0 (c) 組は出たが確かめで落ちた（理由ごと） (d) 出た
4. 既存の数（上層の負例・hard negative・C 群・決定性・段2 への原文の漏れ・お手本の再現）はそのまま残す
5. 結果の Markdown に、物差しの版（`labels_v1` の sha256・`synthetic_v1` の sha256）を書く

## 3. 確かめの述語を広げる（`src/explanation.py`）

架空の組とあなたの組で、**正しい説明が述語の確かめで落ちる**ことが分かった。

| 関係 | いまの述語 | 落ちる例 |
|---|---|---|
| R1（経験） | `てきた` | 「〜を担当しました」「〜にも出店しました」（L10・L16 と架空の2組） |
| R2（申告） | `できる\|関われる\|手伝える` | 「〜を手伝えます」「〜できます」 |

- R1：過去の経験を表す文末（「〜てきた」「〜てきました」「〜ました」「〜した」など）を受け付けるように広げる
- R2：丁寧の形（「〜できます」「〜関われます」「〜手伝えます」）を受け付ける
- **広げすぎない**：願望（「〜したい」「〜と思っている」）や、関係の無い過去（「〜が好きだった」）を R1 として通さないこと
- 正規表現の案と、**両方の物差しの全組に当てた結果**（通るもの・落ちるもの）を報告する。述語は確かめの一部なので、生成仕様の §13 の後ろに「v0.6 の追記」として書き、確かめの版を上げる
- **この変更の前に、§4 の報告で止まる**
