# 実装指示書 75 — ダークモード（全ページ）と、色の定義の一本化

**作成:** Claude（KAORU の依頼・2026-11-15）
**ゴール:** G1〜G3 のどれにも直接は当たらない。利用者を迎える準備（全画面の見た目）
**層:** 4（表示）。画面の色だけ。説明の中身・照合・記録には触れない
**根幹か枝か:** 枝

---

## なぜ作るか

- 利用者を増やす段階に入るので、暗い画面を好む人にも読みやすくする
- いまは色が 22 のページに直接書いてある（約 520 か所・約 120 種類）。色に名前を付けて 1 か所にまとめれば、暗い色の組を足せるうえ、今後の色の直しも 1 か所で済む

---

## 0. 変えないもの

- **文・並び・HTML の構造。**変えるのは色（CSS）だけ
- **説明の表示の HTML。**保存済みの表示も、新しく描く表示も、HTML は一字も変えない（承認した人の表示のハッシュ・pair_digest が変わらないこと）。色は、クラスに当てる CSS だけで変える
- **明るい表示の見た目。**今とほぼ同じに保つ（§2 の寄せで変わるところは報告する）
- サーバーに何も保存しない。クッキーも足さない。ログにも出さない
- ロゴの文字「PoX」・画面の文言
- 外部の読み込み（フォント・アイコン・ライブラリ）を足さない

---

## 1. 色に名前を付けて、1 か所にまとめる

- 色の名前（CSS の変数）を、`templates/_base.html` の `:root` にまとめる。すでにある変数（`--ring`・`--ink`・`--navy` など）は、ここに寄せる
- 名前は**役割**で付ける（色の名前で付けない）。目安は 24 個まで。たとえば次の役割

| 役割 | 例 |
|---|---|
| 地 | ページの背景・カードの背景・一段下げた背景・入力欄の背景 |
| 文字 | 本文・補助（薄い文字）・見出し・リンク・押せない状態 |
| 線 | 枠線・区切り線・フォーカスの輪 |
| ナビ | ナビの背景・ナビの文字・メニューの背景 |
| 強調 | 主なボタンの背景と文字・印（新しいやり取りなど）の背景と文字 |
| 状態 | 注意・誤り・成功の、文字と背景 |
| 説明の画面 | 受けた人の側の帯・申請者の側の帯・関係のラベル・やり取りの自分と相手の線 |

- 最終の名前の一覧は、報告に表で書く（名前・役割・明るい色・暗い色）

## 2. 直接書いた色を、名前に置き換える

- 対象は、全部のテンプレートの `<style>`・部品に直接書いた `style="…"`・画面を組み立てる JavaScript の中の色・`src/` と `app.py` が出す HTML の中の色
- 近い色は、同じ役割の 1 つに寄せる（約 120 種類 → 24 個まで）
  - 寄せたことで、明るい表示の見た目がはっきり変わるところは、報告に書く
- **説明の表示の HTML には、色を足さない・書き換えない**（§0）

## 3. 暗い色の組

- `<html data-theme="dark">` のときに、§1 の名前へ暗い色を当てる。色の定義はこの 1 か所だけ
- 守ること
  - 文字と地の明るさの差（コントラスト比）は、本文で 4.5 以上、大きな見出しと印で 3 以上
  - 地は真っ黒（#000）にしない。文字は真っ白（#fff）にしない
  - ナビの紺を基調にして、明るい表示と同じサービスに見えること
  - 色だけで意味を伝えない（側の帯・状態・やり取りの線は、今までどおり文も出す）
  - 入力欄・ボタン・スクロールバーも暗くなること（`color-scheme` を当てる）
  - 影は、暗い地では薄くするか、線に替える
- 利用者が上げた画像には手を加えない

## 4. 切り替えのボタン

- **置き場所:** ナビの「コミュニティ」の右。全ページ共通の部品（`templates/_nav.html`）に 1 つ
- **印:** 太陽と月。絵文字ではなく、埋め込みの SVG で描く
  - 明るい表示のときは月（押すと暗くなる）、暗い表示のときは太陽（押すと明るくなる）
- **読み上げ:** `aria-label` を「表示を暗くする」／「表示を明るくする」に切り替える
- **最初の見え方:** その人の端末の設定（`prefers-color-scheme`）に合わせる。ボタンで選んだ後は、選んだほうを使う
- **覚える場所:** その人のブラウザの中だけ（`localStorage`）。ログインしていなくても使える
- **ちらつきを出さない:** ページを描く前に決める（`<head>` の先頭の短いスクリプトで `data-theme` を付ける）
- **狭い幅:** iPhone の幅でも、ナビが 2 行になったり、はみ出したりしないこと。入らないときは、勝手に場所を変えず、案を報告する

## 5. この指示書でしないこと

- 3 つ目の選択肢（「端末に合わせる」に戻すボタン）を作らない
- 色以外のデザインの直し（余白・文字の大きさ・並び）をしない
- 選んだ表示をサーバーに保存しない
- メール・印刷の見た目は対象にしない

---

## 6. 成功の条件

1. 全部のページが、暗い表示で読める（白い地が残らない・読めない文字が無い）
2. 明るい表示が、今とほぼ同じに見える
3. ボタンで切り替わり、ページを移っても、開き直しても、選んだほうのまま
4. 開いた瞬間に、反対の色がちらつかない
5. 説明の表示の HTML・表示のハッシュ・pair_digest が変わらない
6. 既存のテストが通る

**失敗したときに結論すること:** あるページで、暗い表示にできない部分が残ったら、そのページと理由を報告に書く（黙って明るいまま残さない）。

---

## 7. テスト（例。番号は今の続きで付ける）

1. テンプレートと、HTML を出すコードに、色の直書きが残っていない（`_base.html` の色の定義を除く。除外するものがあれば、一覧にして理由を書く）
2. 色の名前のすべてに、明るい色と暗い色がある
3. 文字と地の組のコントラスト比が、§3 の線を満たす（明るい・暗いの両方。計算で確かめる）
4. ナビにボタンがあり、`aria-label` が状態で切り替わる
5. 保存した選択があれば、それを使う。無ければ、端末の設定に合わせる
6. 説明の表示の HTML が、この変更の前後で一致する（保存済みの見本と、新しく描いたものの両方）
7. サーバーへの保存・クッキーが増えていない

## 8. 順番と止まるところ

- **指示書73 の順3 が先。**その後に、この指示書に進む（一度に一つずつ）
- 順1：§1・§2（色の名前にまとめる。明るい表示は変えない）→ PR
- 順2：§3・§4（暗い色の組と、切り替えのボタン）→ PR
- **止まらない。**ただし、ナビにボタンが入らないとき（§4）だけは、報告して止まる
- マージの後、KAORU が本番で見て、色の調整を伝える（色は 1 か所なので、直しは小さい）

---

## 9. 報告の形

1. 禁則抵触の有無／推測で補完した箇所
2. 色の名前の一覧（名前・役割・明るい色・暗い色・コントラスト比）
3. 寄せたことで、明るい表示の見た目が変わったところ
4. 暗い表示にできなかったところ（あれば）
5. PR 番号・テストの番号と件数・全体の件数
6. スクリーンショット（合成データ。明るい・暗いの両方）
   - つながる・相手のプロフィール（説明）・受信箱の一覧・詳細（承認）画面・マイページ・言語化する・コミュニティ・ログイン・プライバシーポリシー
   - 広い幅と、狭い幅（iPhone の幅）
