## 0. 変えないもの・守ること

- 本番のフラグ・画面・DB・プライバシーポリシーに触れない（本番の生成は止めたまま）

### 1-2. モデルのファイル

- 形は GGUF、圧縮は **Q4_K_M**（確かめ用のデスクトップの 8GB の GPU に載る形。試験と確かめで同じファイルを使うため）
- 手に入れ方の順

  2. 1 ができないときだけ、第三者の GGUF を使う。出どころ・ファイルの sha256・そのページのライセンスの記載を記録する
- どちらの道になったかを、候補ごとに報告に書く
- 使うファイルは、KAORU の Hugging Face のアカウントの**非公開**の置き場所にも置く。走らせるときは、そこから取る

### 1-3. 動かす環境

- Hugging Face の **Jobs**。GPU は **L4（24GB）1枚**に固定する（T4 は使わない）
- llama.cpp は、**版（commit）を決めて固定**する。入れ物は digest で指定する
  - Jobs が受け付ける入れ物の置き場所に限りがあるときは、同じ中身の入れ物を、受け付ける場所に置く。作り方（Dockerfile・元の入れ物の digest）を残す
- 生成の設定（全部を記録する）
  - 温度 0・貪欲（top-k 1・top-p 1）・seed 固定・繰り返しの罰なし
  - 並列 1・バッチ 1
  - 文脈の長さ・出す長さの上限・止める印
  - チャットの型は、モデルのファイルに入っているものを使う。描いた後の入力のバイト列の sha256 を記録する
- 出力の形は、文法の縛りで JSON に縛る（段1・段2 それぞれ、いまのスキーマに合わせる）。縛りの定義の sha256 を記録する
- Nemotron は考える機能を切る。切れていること（考える部分が出力に無いこと）を確かめる

### 1-4. 記録する一式（候補ごと）

モデルのファイルの sha256・公式の revision・圧縮の形・llama.cpp の commit と作り方の設定・入れ物の digest・GPU の種類・ドライバと CUDA の版・生成の設定・文法の sha256・プロンプトの sha256・物差しの sha256・かかった時間と費用。

## 2. 測るもの

物差しは、架空の 60 組（`synthetic_v1`。sha256 `01823523…`）。入力の形は、指示書72 のとおり「1 つの必要 × 1 つの相手の文」。

| 中身 | 組の数 | 測ること |
|---|---|---|
| 説明できない | 25（うち「無関係」が 10） | 説明を出してしまった数（誤り） |
| 説明できる | 28（うち、規則で出さない 4） | 説明を出せた数（拾えた。分母は 24） |
| 判断できない | 7 | 生成しない（今までどおり） |

あわせて測る（線には入れないものを含む）。

- 関係の一致（厳しい側）・関係ごとの拾えた・結果の種類（a〜d）・確かめで落ちた理由
- 段2 に原文が漏れていないこと
- 決定性：60 組すべてを 5 回走らせ、出力が一字ずつ同じか
- 1 件あたりの時間・GPU のメモリ・起動にかかる時間・費用（段階3b の見積もりに使う）
- できれば、選ばれた字と次点の字の差（小さいところが、機械を替えたときに変わりやすい）

**橋渡しの組：**60 組のうち 12 組を、あとでデスクトップでも走らせる（機械の差と、物差しの差を分けて見るため）。選び方は、説明できる 6・説明できない 6 を、id の小さい順に、関係（R1〜R4）と「無関係／近い話題」が偏らないように取る。**選んだ id を、走らせる前に報告に書く。**

**基準の出力：**合格した候補の、60 組の出力（架空の文だけ）を、sha256 と一緒にリポジトリに保存する。機械を替えるたびに、これと比べる。

## 3. 合格の線（事前登録。結果を見る前に固定する）

次の**すべて**を満たした候補を「機械の線に合格」とする。

| # | 線 | 中身 |
|---|---|---|
| 1 | 誤り | 説明できない 25 組で、説明を出した数が **1 以下**。うち「無関係」の 10 組では **0** |
| 2 | 拾えた | 24 組のうち **17 以上**（70% 以上） |
| 3 | 規則で出さない | 4 組で、説明を出した数が **0** |
| 4 | 原文の漏れ | **0** |
| 5 | 決定性 | 5 回とも、60 組の出力が同じ |

- 「誤りが 0 だった」ことを、偽陽性の率として書かない。「この物差しの試験を通った」と書く
- **2つとも合格したとき：**誤りの少ないほうを選ぶ。同じなら、拾えた数の多いほう。拾えた数の差が 2 組以内なら、KAORU の方針（米国）で Nemotron を選ぶ
- **1つだけ合格したとき：**その候補を選ぶ
- **どちらも合格しないとき：**どの線で落ちたかを報告して止まる。線・プロンプト・確かめを、結果に合わせて動かさない。次の手（gpt-oss-20b を試す・設計を見直す）は KAORU が決める

この後に、人の評価（§4）と、48 組での確かめ（別の指示書）がある。3つとも通って、はじめて「選んだ」とする。
