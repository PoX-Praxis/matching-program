## 2. 動かし方を一つにそろえる（HF Jobs と PC で同じもの）

### 2-1. 推論のエンジンを llama.cpp にそろえる

- 理由：gpt-oss-120b は、家庭用の GPU では vLLM で動かせない（重み 65GB が GPU に載らない）。llama.cpp なら、専門家の重み（MoE）を主メモリに置いて動かせる。**HF Jobs も同じエンジン・同じモデルのファイルにすれば、12/6 に変わるのは機械だけになる**
- モデルのファイル：gpt-oss-120b の公式の GGUF（MXFP4。公式の重みから作られたもの）。リポジトリ・revision・ファイルの sha256 を固定する。公式のものが無ければ、公式の重みから決めた版の変換の道具で作り、作り方を残す
- llama.cpp：版（commit）を固定する。入れ物（Docker image）を 1 つ作り、digest で固定する。**HF Jobs も PC も、この同じ入れ物を使う**
- サーバーの形：OpenAI 互換の HTTP（`/v1/chat/completions`）。推論先の窓口 `local_http` から、そのまま呼べる形にする

### 2-2. 生成の設定（一か所にまとめる）

`config/explain_runtime.toml`（名前は任せる）を、**HF Jobs と PC の両方が読む唯一の設定**にする。中身：

- モデル：リポジトリ・revision・ファイル名・sha256
- エンジン：llama.cpp の commit・入れ物の digest
- 生成：温度 0・seed 0・reasoning_effort medium・出す長さの上限・文脈の長さ・同時 1（`--parallel 1`）
- 置き場所：GPU に載せる層（`-ngl`）・主メモリに置く専門家の数（`--n-cpu-moe`）。**機械ごとに変えてよい唯一の項目**（GPU のメモリで決まる）
- プロンプトの sha256（2 つ）
- 切る候補（`EXPLAIN_CELLS=A`）

### 2-3. 版の記録（カードごと）

根幹 §4-4 のとおり、カードに残す：モデル・revision・ファイルの sha256・エンジンの commit・入れ物の digest・GPU の名前・置き場所の設定・生成の設定・プロンプトの sha256・推論先（`hf_jobs`／`local_http`）・コードの commit・作った時刻。

## 3. 本番の流れ（設計方針 §2〜§4 のとおり）

- 作る予定（キュー）：登録・更新で、作る組を積む。どちらかが更新したら、その組を 1 回だけ作り直す。承認された説明は「承認したときの説明」として残す
- 推論先の窓口：`POX_EXPLAIN_BACKEND=hf_jobs | local_http`
  - `hf_jobs`：たまった組を、1 回の起動でまとめて作る。間隔は 1 日 1 回（予定が無ければ起動しない）
  - `local_http`：予定が入ったら、すぐ作る。PC が止まっていれば予定に残し、戻ったら作る
- 作れていない組は、画面に出さない（「準備中」とも出さない）
- 許可リスト：KAORU×PA だけ
- **表示のフラグは切ったまま。**KAORU が KAORU×PA の画面を見て、よいと言ったら入れる

## 4. PC で同じ状態を作るための一式（12/6 に KAORU が使う）

リポジトリの `deploy/local_inference/` に置く。KAORU が読んで、一つずつ進められる形にする。

| もの | 中身 |
|---|---|
| `README.md` | やさしい日本語の手順。下の §4-1 |
| 必要なものの表 | GPU のメモリ 24GB 以上・主メモリ 64GB 以上（96GB あると余裕）・空きディスク 100GB 以上・NVIDIA のドライバ・Docker（Windows なら WSL2）。GPU のメモリごとの `--n-cpu-moe` の目安 |
| モデルを取る道具 | 固定したリポジトリ・revision から取り、sha256 を確かめる。違えば止まる |
| 起動の道具 | §2-2 の設定を読んで、同じ入れ物でサーバーを起動する |
| 確かめの道具 | ①サーバーが返事をするか ②短い固定の文（架空）で、JSON が返るか ③1 秒あたりのトークン数を表示する |
| 自動で立ち上げる設定 | PC の起動時・止まったときに、サーバーとトンネルを立ち上げ直す（Windows・Linux の両方の例） |
| トンネル | 埋め込みの計画と同じやり方。PoX（Render）からだけ呼べるように、鍵（環境変数）で守る |
| `.env.example` | 変数の名前だけ。値は書かない |

### 4-1. README の手順（KAORU がすること）

1. GPU の名前・GPU のメモリ・主メモリを確かめる（確かめ方を書く）
2. 必要なもの（ドライバ・Docker）を入れる
3. モデルを取る道具を動かす（sha256 の確かめまで自動）
4. 起動の道具を動かす。GPU のメモリに合わせて `--n-cpu-moe` を選ぶ（表から）
5. 確かめの道具を動かす。1 秒あたりのトークン数を Claude に伝える
6. トンネルを立てる。Render の環境変数を `POX_EXPLAIN_BACKEND=local_http` に替える
7. KAORU×PA を作り直す。**HF Jobs で作ったものと、pair_digest・目的の状態が同じなら「同じ状態」**。画面でも一度見る
8. 自動で立ち上げる設定を入れる

7 で違ったときは、HF Jobs の版のカードを残したまま止まり、Claude に伝える。
