# PoX 本番設計ノート（実験フェーズ知見の還流）

`exp/embedding-model-eval`（1,090件・3モデル比較・KH人手評価）で得た、本番設計に効く知見を集約。
実験の詳細レポートは同ブランチの `eval/analysis/final_report.md`（決定）・`mrl_report.md`・
`limiting_axis_investigation.md`（gitignore・要参照時は当該ブランチ/手元）を参照。

---

## 1. 採用決定の要約

- **採用埋め込みモデル: `nomic-embed-text-v2-moe`（Apache 2.0）**。本番は**フル 768次元**で設計。
- 位置づけは **暫定チャンピオン方式**（決定的な精度差は未検出。より良い候補が出れば差し替え可能な構え）。
- 決め手（決定ルール ①人手評価→②ライセンス/説明可能性→③MRL→④較正）:
  - ①人手評価は**差が小さく本装置では検出不能**（seeker n=1・会いたい度が3〜4に圧縮・検定未実施）。独立信号は1勝1敗。
  - ②-2 ライセンスで **EmbGemma 脱落**（Gemma独自・gated・使用制限の派生物伝播義務）。残る Apache2.0 勢のうち、
    供給リスク低・監査性（学習データ公開）・コスト（768次元・MoE効率）で **Nomic 優位**。**ここが決め手**。
  - ③MRL256 は全モデル不合格だが**測定失敗の疑い**（固定パラメータのフル次元前提）＝決定根拠に用いない。
  - ④較正テストは3モデルとも 12/12 で差なし。
- 詳細と限界（seeker=1名・必要像一本・TOP30範囲制限・真の偽陰性は測定不能）は `final_report.md §8`。

## 2. スケール戦略の発火順（段階発火・母数 N に応じて）

前段が限界に達したときのみ次段に着手（早すぎる最適化を避ける）。

1. **現状維持：フル768次元・総当たり**（N〜10⁵）。採用 nomic のフル次元で全候補スコアリング。追加実装なし。
2. **int8 量子化**（メモリ圧が出たら）。※ **MRL256 の失敗は量子化の失敗を予測しない**（別現象）ため、**量子化は別途検証が必要**。
3. **10⁵超：GPU 総当たり＋ハード要件 prefilter**（地域・言語・所属などの決定的条件で母集団を機械的に絞ってからスコアリング）。
4. **10⁶超：retrieve-then-rerank**。支配チャネルの ANN → **寛容な shortlist（大きめ k）** → 合成式で厳密再ランク。
   リコールは「合成 TOP-k を正解」とみなして較正する。
   - **重要（下記§3の含意）**：合成式 M_p(p=-0.3) は **min支配ではなく幾何平均相当**。単調ではあるが連言性は弱いため、
     **支配チャネル1本の純ANN top-k は他チャネルで強い候補を取りこぼす**。ANN段は**寛容 shortlist 必須**（純単一チャネル足切りは不可）。
5. **密度機能（分布ベースの足切り・shortlist）は索引成立後**。前提: b チャネルの幾何・合成式のテール質量・
   絶対値でなく相対値での判断・**実成果ループ（接続成否ラベル）が必須**。索引が無い段階では蓄積のみ（judgment は将来）。

**検証前提（各段共通）:** 合成式の単調性確認・律速軸分布の監視（単一軸への退化検出）。
**MRL 装置修正（256用再較正）は優先度引き下げ**（フル768で当面回すため）。

## 3. 律速軸退化の結論（合成式の健全性）

TOP30 の limiting_axis が3モデルとも単一軸に潰れた現象（Qwen3/Nomic=全件a、EmbGemma=全件b）の究明結果：

- **ランキング自体は健全**：合成 `M_p`（p=-0.3）は各チャネル類似度に対して**単調増加**で、**3チャネルが乗算的に寄与**して順位が決まる（≈幾何平均）。
- **単一軸 ≠ 単一チャネル支配**：limiting_axis は「最も低スケールのチャネルを報告する診断ラベル」に過ぎず、順位が1チャネルで決まっている証拠ではない。
- **原因**：主に **(iii) チャネル間スケール非対称**（encoding 由来・母数非依存）＋ **(ii) 重み/γゲートの増幅**（c は log係数0.164で構造的に律速から排除、a/b の僅差を重みが単一軸へ均す）＋ **(i) プール均質**（各chの std 小で全件均一化）。
- **設計含意**：
  - (A) 「p=-0.3 は min支配だから単一チャネルANNで代表できる」という前提は**否定**（数値上ほぼ幾何平均）。→ §2-④の**寛容 shortlist 必須**の根拠。
  - (B) 単一軸退化は**緊急のランキングバグではない**（プール多様化でも消えない encoding 由来だが、順位は健全）。
    改善対象は **limiting_axis という診断の設計**：律速判定の前に**チャネル別スケール正規化**（z-score / per-channel 較正）を挟むと「本当に足を引っ張るチャネル」を指すようになる。**優先度=中**。
- **本番最優先の検証**：律速軸の退化監視・負コントロール（無関係候補で偽陽性を測る）・複数 seeker での再評価（n=1解消）。

## 4. セキュリティ制約（絶対厳守・実験中も適用）

- `ANTHROPIC_API_KEY` / `GITHUB_TOKEN` / `DATABASE_URL` はコードにもリポジトリにも書かない。
- `.env` / `*.key` / `secrets.json` はコミット禁止。`*.db` は gitignore。
- 個人プロフィール由来の生成物（`eval/github_profiles.jsonl` / `eval/my_profile.json` / `eval/cache/` / `eval/analysis/`）は gitignore・非コミット。
- `seeker` カラムは viewer/public API レスポンスに絶対出さない。`GET /profile/<id>` は `get_profile_view()` のみ（`get_seeker()` を呼ばない）。
