## 6. HMAC の鍵（§4。作るのは §9-3）

- **名前:** `POX_EXPLANATION_DIGEST_KEY`
  - 32 バイト以上の乱数
  - `POX_SECRET_KEY`・`POX_EMAIL_SALT` とは独立させる
- **使い方:** `render_digest = HMAC-SHA256(鍵, その人が見た表示の HTML の UTF-8)`
- **起動の条件:** `POX_EXPLANATION` が `allowlist` か `on` で、鍵が無いか短ければ、本番は起動しない（テスト §7-9）
  - 開発（`POX_DEBUG=1`）だけ、固定の開発用の鍵を使う
- **出さない:** 鍵はコードにもログにも出さない。起動のログには「設定あり／なし」だけを出す
- **替えるとき:**
  - 記録ごとに鍵の識別子（`digest_key_id`）を添える。鍵で固定の文字列の HMAC を取った先頭 8 桁で、鍵そのものは分からない
  - 新しい鍵にしたら、新しい記録は新しい鍵で取る
  - 古い記録は、`POX_EXPLANATION_DIGEST_KEY_PREV`（任意）で確かめられるようにする
  - 鍵は、漏れたときのほかは替えない

3. `POX_EXPLANATION_ALLOWLIST` に `@KAORUのハンドル+@PAのハンドル` を入れる
4. `POX_EXPLANATION` を `allowlist` にする → デプロイ
5. 起動のログに `[explanation] mode=allowlist digest_key=設定あり` が出ることを確かめる（鍵そのものは出ない）
- 戻すときは `POX_EXPLANATION=off`（既定）。画面と API は今と同じに戻る。保存した表示は DB に残る

## 6. HMAC の鍵の名前と扱い

- 名前: `POX_EXPLANATION_DIGEST_KEY`（32 バイト以上）。`POX_SECRET_KEY`・`POX_EMAIL_SALT` とは独立
- `render_digest = HMAC-SHA256(鍵, その人が見た表示の HTML の UTF-8)`。申請した人の表示（画面2）と、承認した人の表示（画面3）の 2 つを取る
- 記録ごとに鍵の識別子（鍵で固定の文字列の HMAC の先頭 8 桁）を添える。鍵そのものは分からない
- 替えるとき: 新しい鍵を `POX_EXPLANATION_DIGEST_KEY` に、古い鍵を `POX_EXPLANATION_DIGEST_KEY_PREV` に入れる（古い記録を確かめられる）。漏れたときのほかは替えない
- `allowlist`・`on` で鍵が無いか短ければ、本番は起動しない。開発（`POX_DEBUG=1`）だけ固定の開発用の鍵
- 鍵はコードにもログにも出さない。起動のログは「設定あり／なし」だけ
