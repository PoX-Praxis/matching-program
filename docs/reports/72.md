## 3. §4-2 計測の形（`scripts/explanation_measure.py`）

### 3-1. 組ごとの入力の作り方

**N（必要を出した側）:** 1 つの目的に、1 つの必要（その組の必要）だけを置く

| 物差し | 目的の見出し | 目的の種類 | 欠かせない要素 |
|---|---|---|---|
| 架空 | その人の `purpose` | その人の `種類` | 組の `must` |
| KAORU の 48 組（`need_key` が 1-x・2-x） | KAORU の公開の JSON の、その目的の向かう先 | 目的全体から仮の規則（指示書69 §4-4）で決める（目的1＝補完・目的2＝共鳴）。1 つの必要だけから決め直さない | KAORU の JSON のとおり |
| KAORU の 48 組（`need_key` が PA。L07〜L09） | 空（PA は v4 で、目的の見出しが無い） | 補完 | 欠かせない要素とする（v4 の必要は 1 つだけなので） |

- PA（v4）の向きは、本番では生成しない（v5 の人だけ）。L07〜L09 は、モデルを測るためだけの組になる

**O（相手）:** 相手の文 1 つ（`other_kind` で置き場所を分ける）

| 相手の文 | 置き場所 |
|---|---|
| 「PA の現状（全文）」（L01〜L06） | 現状の欄に分ける（持っているもの・動き方の型）。「縛られているもの」は O の側では使わない（本番と同じ） |
| 「関心の文」（L43〜L48） | 関心 |
| そのほか（架空の組を含む） | 与え像の 1 文 |

- 架空の組は、文の種類（与え像か関心か）を持っていないので、すべて与え像として置く

### 3-2. 数え方

数えるのは、物差しごとと合計です。

| 数 | 定め方 |
|---|---|
| **誤り** | `説明できない` の組で、説明を出した数 |
| **拾えた** | `説明できる`（R を含む）の組で、説明を出した数 ÷ `説明できる` の数 |
| **関係の一致** | 出した説明の組の関係が、すべて `expl_label` に含まれる数 |
| `判断できない`・`対象外` | 生成しない。件数だけ書く |

- 「出した」とは: 確かめを通って、その目的が `explained` になったこと（＝画面に出る）
- 関係ごとの拾えた数（R1〜R4）も、件数で書く

### 3-3. 1 回ごとの記録（文は記録しない）

組ごとに、次を JSON に残します。
- 組の id
- 結果の種類:
  - (a) JSON として読めなかった（段1）
  - (b) 読めたが組が 0
  - (c) 組は出たが確かめで落ちた（理由ごと）
  - (d) 出た
- 出した組の関係
- 段2 まで進んだか

(a) と (b) は段1 の生の出力から決めます。生の出力そのものは残しません。

### 3-4. そのまま残すもの

- 上層の負例（4 人）・hard negative・C 群・決定性・段2 への原文の漏れ・お手本の再現
- 前の「48 対の応える／応えない」（`final` で数えていたもの）は、3-2 の数え方に置き換える

### 3-5. 書き出し

- KAORU の 48 組が無いとき（CI・ほかの人の環境）は、架空の組だけで動く
