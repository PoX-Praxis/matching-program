## 2. 順1: 組み直しのやり方（§1-4）と見出しの文の案（§1-2）

### 2-1. 組み直しのやり方: 保存した HTML を切り分けて並べ直す

申請の時には、次の 2 つを保存している（`explanation_renders`）。

- 申請者が読んだ表示の HTML（`symbolic_html`。呼び方は記号のまま）
- 確かめを通ったカードの JSON（`card_json`）

選んだのは **HTML の切り分け**。

| やり方 | 文が変わらないか | 選んだか |
|---|---|---|
| A. 保存した HTML を切り分けて並べ直す | 変わらない（切れ端をそのまま使う） | **選んだ** |
| B. 保存したカードの JSON から、いまのレンダラで描き直す | レンダラの版が変わると変わりうる | 選ばなかった |

**仕組み**

- v0.8 から、レンダラは印を入れる。印は HTML の注記なので、画面には出ない
  - 本体の向きを `<!--ex:main-->…<!--/ex:main-->` で囲む
  - 逆の向きを `<!--ex:rev:p|s-->…<!--/ex:rev-->` で囲む
  - 目的の枠ごとに `data-number` を付ける
- 画面3 は、この印で切り分けて並べ直す（`incoming_layout`）
  - 受けた人の目的の側（逆の向き）を先に、申請者の目的の側（本体）を後に置く
- 足すのは次だけ
  - 側の見出し（決まった型）
  - 受けた人の側の要旨（要旨の型）
- 逆の向きの見出し「── ⟦T⟧から見た⟦V⟧ ──」は、側の見出しに置き換える
- 印の無い表示（74 より前に保存した申請）は、前の形のまま出す（`incoming_html`）

**確かめたこと**

- 合成データの全部のカードで、組み直す前と後の文を比べた（テスト 467）
  - 増えた文は、側の見出しと受けた人の側の要旨だけ
  - 減った文は、逆の向きの見出しだけ
  - 目的の枠は、全部そのまま残る

**承認の時に残すもの**

- 承認した人の表示のハッシュ（`recipient_digest`）は、詳細の画面で実際に見た表示（組み直した形・根拠は閉じた形）のハッシュ（テスト 469）
- 補足の欄・やり取りは含めない
- 合意の記録（pair_digest）は、今までどおり保存したカードの組から作る

## 3. 順2（止まるところ）

#### (1) 保存の形と API

**新しい表 `explanation_exchanges`（案）**

| 列 | 型 | 中身 |
|---|---|---|
| `id` | TEXT PK | `ex_…` |
| `render_id` | TEXT NOT NULL | 申請に添えた表示（`explanation_renders` の行）＝ その申請 |
| `from_subject` | TEXT NOT NULL | 書いた人 |

- 申請との結びつけは、申請に添えた表示の行（`render_id`）にする
  - 説明の表示は、申請者と受けた人の 1 組に 1 つで、見送り・取り下げ・承認と同じ時に動く
  - このため、消す・残すが表示と一緒に決まる
- 台帳・pair_digest・render_digest・ログには入れない

**API（案）**

- `GET /api/explanations/exchange?with=<相手>`
  - 返すもの: 状態（open／closed／none）・申し出の文・発言の並び（書いた人のユーザー名・本文・日付）・まだ書けるか
  - 当事者の二人だけが呼べる。開いた人宛ての発言を「読んだ」にする
- `POST /api/explanations/exchange {to_id, text}`
  - 申請中（pending_out／pending_in）で、申請に表示が添えられているときだけ書ける
  - 次のときは弾く
    - 400 字を超える
    - 上限（下の (6)）を超える
    - 申請中でない（成立・見送り・取り下げの後、または申請が無い）
- `GET /api/my/offers`
  - 一覧の印のために、行ごとに「新しいやり取りがあるか」（真偽だけ）を足す

**いまの `explanation_supplements`（kind = self／approve／decline）との関係**

- `approve`
  - 新しくは書かない。承認に添える補足は、やり取りに置き換える
  - すでにある行は、今までどおり承認時の説明に出す
- `decline`
  - 下の (4) の案なら、新しくは書かない
  - すでにある行（届ける前のもの）は、今の仕組みで一度だけ届けて消す
- `self`
  - 変えない（下の (8)）

**入力の手当て**

- いまの補足は、前後の空白を除くことと 400 字の上限だけ
- 画面に出すときは HTML のエスケープをしている
- 制御文字は除いていない
- 指示書の「いまの補足と同じ」に合わせると、やり取りも同じになる
  - 案: やり取りでは、制御文字・ゼロ幅文字も除く（説明の生成の入力の手当てと同じ）

**確かめたいこと（A）: 説明が無い申請でも、やり取りを使えるようにするか**

- 案: 説明の表示が添えられた申請（説明のフラグが通った組）だけにする

- すべての申請に広げるなら、結びつけを申請（`connection_requests`）にし、ポリシーの文も 6-2 の外に書く
