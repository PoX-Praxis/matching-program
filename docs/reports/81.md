## 1. 禁則抵触の有無／推測で補った箇所

**禁則抵触：なし。**
- 新しい計測のテスト（3 回の一致・最小対・初期カードとの比べ）は入れていない。足したのはコードの単体のテストだけ（架空の人・偽の推論先）
- プロンプトは `prompt_label_v0.3`・`prompt_select_v0.1` のまま（sha256 02ec1ca8…・19e818fb…。設定と起動のときに確かめる）
- 外部の AI のサービスは使わない。gpt-oss-120b を、PoX が管理する入れ物（HF Jobs の非公開のジョブ・PC）で動かす
- KAORU・PA の文は、リポジトリ・ログ・この報告に無い（新しいファイルを全部の欄の 8 字の切れ端で照合して、足した当たり 0）。鍵・トークン・URL はリポジトリに無い（環境変数の名前だけ）
- 数値を画面と公開 API に出していない。表示のフラグ（`POX_EXPLANATION`）は切ったまま（off）。モデルは走らせていない（入れ物の確かめに CPU のジョブを 5 回、合わせて 1 分ほど。費用は 1 セント未満）

**推測で補った箇所（KAORU が見て決めてよいもの）：**
- **入れ物は自分で作らず、llama.cpp の公式の入れ物を digest で固定した。** この repo で決めてあった llama.cpp の版（commit b1b770d・build 12359）と同じ版の公式の入れ物（`server-cuda12-v1.0.0-b12359-b1b770d`）がある。HF Jobs が ghcr.io の入れ物を動かせることを、CPU の小さなジョブで確かめた（bash・curl・python3 も入っている）。PC も同じ digest を使う
- **モデルのファイル**：OpenAI は GGUF を出していないので、llama.cpp の開発元（ggml-org）が公式の重み（openai/gpt-oss-120b）から作った MXFP4 の GGUF を使う（1 ファイル・63.4GB・Apache-2.0）
- **hf_jobs の呼び方**：ジョブの口（ポート）を公開し、llama-server の鍵（ジョブごとに作る。暗号化した環境変数で渡す）で守る。Jobs の口の鍵（HF のトークン）を本番の画面の側で毎回使わないため
- **流れを Render で動かす**：local_http（PC）では、PoX（Render）が PC の llama-server を呼ぶ（指示書の形）。部品を作るには形態素解析が要るので、fugashi・unidic-lite を本番の requirements.txt にも入れた（指示書77a では「本番に入れない」としていた。テスト 526 を改めた）。メモリは 70MB ほど増える
- **確かめの分け方**：本番の確かめ（`X.check`）のうち、仕様 v0.4 の形の決まり（句は 40 字まで・R1/R2 の述語・① の閉じた語彙・① に {O} が必ずある・必要の要素は need の参照だけ）は、流れのカードには当てない。当てると KAORU×PA のカードがすべて落ちる（v06 で確かめた）。安全の確かめ（引用が原文にあるか・その目的のものか・向き・連絡先・禁止の語・名前・「あなた」・組に無い数値・根拠の印）はそのまま当てる。流れのカードは、generation のラベルのプロンプトの sha256 で見分ける（`X.is_pipeline`）
- **入力**：KAORU×PA の試しの欄と同じ（目的・必要像・与え像・関心・現状・意志（なぜ）・背景・経験）。公開の閾値を過ぎたものだけ、「縛られているもの」は本人が選んだときだけ、目的の種類は本人が選んだもの（無ければ規則）。**意志（なぜ）・背景・経験は、いまプロフィールで第三者に出していない欄**で、カードの引用に出る。表示のフラグを入れる前のプライバシーポリシーの改訂（§5 順4）で扱う
- **1 日 1 回**：Render の入れ物の中で、10 分ごとに「予定があり、前の回から 24 時間たったか」を見る（入れ物が止まっている間は動かない。起きた後に作る）。まとめて作る間は、入れ物が止まらないように自分の頁を数分ごとに読む
- **作り直しの確かめ**：pair_digest は鍵（POX_EXPLANATION_DIGEST_KEY）が要る。鍵が無いとき（表示を切った本番）は、組の形のハッシュ（目的・状態・要素の参照と関係）で比べる
