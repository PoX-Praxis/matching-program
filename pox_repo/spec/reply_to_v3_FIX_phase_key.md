## 1. 修正依頼（1点だけ）★これだけ直してください

**フェーズの出力キー名を `"phase"` → `"フェーズ"` に変更してください。**

- 理由：マッチングエンジン（`matching_engine_live.py`）は、他の3項目（意志／求めている／能力）と揃えて **日本語キー `seeker["フェーズ"]`** を参照します。値（`mvp` 等の英語5択）はそのままで正しいので、**キー名だけ**日本語に統一してください。
- 補足：これは前回の通達書の書き方が「値＝英語／キー名＝日本語」と不統一だったために生じた齟齬で、v3側の解釈は妥当でした。今回は「v3側でキー名を揃える」方針を採ります（4項目のキー名を日本語で統一）。

### 修正後のイメージ（該当部分のみ）
```json
"seeker": {
  "意志": "...",
  "求めている": "...",
  "能力": "...",
  "フェーズ": "mvp",                         // ← キー名を "phase" から変更
  "_phase_status": "candidate_unconfirmed",  // ← 補助メタはこのまま維持でOK
  "_phase_candidates": ["mvp", "early_validation"]
}
```

## 2. このままで良い点（変更不要・むしろ歓迎）
- **必須3項目（意志／求めている／能力）が要素分離で出ている**。1ベクトルに潰していない＝要件どおり。
- **フェーズ値 `mvp` は5択内（idea/mvp/early_validation/scale/fundraising）で正当**。
- **`_phase_status: "candidate_unconfirmed"` で本人未確定を明示**してくれた点は、通達書の「本人確定が原則・確信なければ明示」を上回る丁寧さ。**この補助メタはそのまま維持してください**（エンジンは名指し参照なので余分キーがあっても壊れません。本人確定後は `confirmed` 等に更新する運用を想定）。
- **`_meta.not_included` でトークン分配・接続成否ラベル・コミュニティ宣言フォーマットを除外明記**。通達書「今回は対象外」を正確に遵守。
- supporting_material（生テキスト／要約文／attention候補／系列素材）も仕様6章どおり。重み付け・予測は未実施＝マッチング側の担当、という分担も守られている。

## 3. 確認方法（参考）
キー名を直した seeker は、`matching_engine_live.py` の入力にそのまま投入できます。これで統合フェーズ（仕様9章）の相互確認は完了扱いになります。
