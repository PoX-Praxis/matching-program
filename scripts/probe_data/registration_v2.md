## 5. 決定規則（要素の層）

### 5-1. 規則

- **偽陽性率:** 役割の 4 要素をまとめた人 × 要素（約 2400）で数え、**片側 95% の上限（Clopper–Pearson）≤ 0.2405%**
  - 0.2405% ＝ 想定の割合 π＝3%・通過率の下限 Se＝70%・precision 90% から出る値（0.03 × 0.70 × 0.10 ÷ (0.90 × 0.97)）
- **通過率:** 役割の 4 要素をまとめた正例の人物（24）の**点推定 ≥ 70%**（両側 95% 区間を併記）
- 両方を満たす作動点が一つでもあれば、その案は「満たす」
- 偽陽性に上限、通過に点推定を使う理由: 誤って開けると体験が割り当てになる（害が大きい）。取りこぼしの害はそれより小さい
- **想定の割合 3% は、いまは実データのない仮定である。** 1%（0.0786%）・10%（0.8642%）の値も参考に出す。3% を動かす場合は規則の変更として扱う
- 要素ごとの値も出す。点推定で 0.24% を超える要素があれば、所見に名前を挙げる
- 読み方の目安（規則ではない。算術だけ）: 約 2400 の試行で上限 ≤ 0.2405% になるのは、**偽陽性が 1 件以下**のとき（0 件 0.125%・1 件 0.198%・2 件 0.262%・3 件 0.323%・4 件 0.381%）
- **通過した背景の文の一覧:** 報告する作動点で通過した背景の文（与え像の形の検証用）の一覧を出す。KAORU が「実際は応えている」とした文を除いた値を**参考として**併記する。**決定は、通過した文をそのまま偽陽性として数えた値で行う**（厳しい側。§12 Q1）

### 5-2. 作動点

- 作動点は**全要素に共通の値 δ**（要素ごとに別の作動点を選ばない）。スコアは案ごとに §6 のとおり
- δ の格子（数値を見る前に固定）:
  - g の差（C2・b-1・b-3 などの g の尺度）: −0.050 〜 +0.150、0.005 刻み
  - R（g そのもの）: 0.600 〜 0.900、0.005 刻み（0.70 を必ず含む）
  - クロスエンコーダ（logit の差）: −2.0 〜 +8.0、0.1 刻み
  - **L のスコア（YES の logit − NO の logit）: −4.0 〜 +4.0、0.1 刻み（81 点）。δ_L ＝ 0 の点を必ず含め、別に報告する**
  - **C2+b-1+L:** C2+b-1 の δ（−0.050 〜 +0.150・0.005 刻みの 41 点）× L の δ_L（81 点）＝ 3321 の組み合わせのすべて
- **報告する作動点:** 規則を満たす作動点のうち通過率が最も高いもの。同じなら δ が大きいもの、さらに同じなら δ_L が大きいもの。曲線全体（作動点ごとの偽陽性率・上限・通過率・期待 precision）も出す
- 作動点の選択と判定に同じ検証用を使う（§12 Q5）。作動点は 1 つの値の掃引で、偽陽性も通過も δ に対して単調なので、楽観に寄る分は小さい。曲線全体を出す

### 5-3. 期待 precision

- `期待 precision = π·Se / (π·Se + (1−π)·FP)`。π＝1%・3%・10%。Se は点推定、FP は点推定と上限の両方で出す

## 6. 案（すべて §5 の規則を当てる）

`q99_n`＝必要像 n（query）× 与え像の形の推定用（passage）の g の 99% 点（`numpy.quantile(…, 0.99)`、線形補間）。`q99_s`＝相手の文 s（passage）× 必要像の形の推定用（query）の g の 99% 点（約 1000 文なら上位 10 番目あたり）。

| 案 | 通過の条件（δ は §5-2 の共通の作動点） |
|---|---|
| R | g(n,s) ≥ δ |
| C2 | g(n,s) − q99_n > δ |
| C2+b-1 | min(g(n,s) − q99_n, g(n,s) − q99_s) > δ（**閾値を 0 に固定しない**。δ＝0 は掃引の一点） |
| C2+b-2（硬い） | C2 を満たし、かつ s が、閲覧者の役割の要素のうち (g(n',s) − q99_n') が最大の要素 n' ＝ n であるとき（s は最も近い 1 要素にだけ使える。同点は要素の番号の若いほう） |
| C2+b-2（軟らかい） | g(n,s) − q99_n > δ + 0.01 × (k(s) − 1)。k(s)＝閲覧者の役割の要素のうち g(n',s) − q99_n' > δ となる要素の数（n を含む） |
| C2+b-3 | C2 を満たし、かつ g(n,s) − max_{n'≠n} g(n',s) > 0（n' は閲覧者自身の**役割の**他の要素。役割の要素が 1 つの人は C2 だけ） |
| C2+b-1+b-2+b-3 | b-1 のスコアで硬い b-2 を当て、b-3 の条件も満たすとき |
| C6m | `BAAI/bge-reranker-v2-m3`（Apache-2.0・revision `953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e`）の logit。logit(n,s) − q99_n^CE > δ（q99_n^CE は n × 与え像の形の推定用の logit の 99% 点） |
| C6m+b-1 | C6m を満たし、かつ g(n,s) − q99_s > 0（**b-1 の相手の側は埋め込みの g で測り、0 に固定する**。尺度の違う 2 つ（logit と g）を同時に掃引しないため。相手の側の 0 は「相手の文が、必要像の形の文集に対する自分の 99% 点を超える」という意味を持つ。§12 Q3） |
| L 単独 | L のスコア（YES の logit − NO の logit）> δ_L |
| C2+b-1+L | min(g(n,s) − q99_n, g(n,s) − q99_s) > δ かつ L のスコア > δ_L（L は全対で 1 回求めた結果を使う） |

- b-1〜b-3 はどれも、閲覧者自身の要素と固定の文集だけを使う（母集団から作らない）
- L の案は役割の 4 要素だけに当てる（関心の文に「役割を満たすか」を問うのは意味をなさない）。関心型の 2 要素の参考値は埋め込みの案だけで出す
- 決定性（同じ入力で 2 回）・母集団非依存性（無関係な人を 0／10／100 人足して判定が不変）は v1 と同じ方法で出す
- 下層の一覧の長さと偽りの件数（N の関数）・較正曲線（δ の帯ごと）も出す

## 8. L（含意の判定）

- **問い:** 「この与え像の文は、この必要像の文の役割を満たすか」の YES／NO。理由文は書かせない。送るのは**必要像の文と相手の文だけ**（生テキスト・根拠は送らない）
- **スコアの取り方:** 生成させず、回答の最初のトークンの位置で **「YES の logit − NO の logit」** をスコアにする（温度 0 と同じく決定的。max_tokens は 1 に相当）。作動点 δ_L を §5-2 の格子で掃引する（小さいモデルは YES か NO の一方に偏りやすく、差が 0 の一点だけでは L を公平に試したことにならない）。δ_L ＝ 0 の点は別に報告する
- **YES と NO の token id（固定。先頭の空白なし・大文字）:** `llm-jp/llm-jp-3-1.8b-instruct` は YES ＝ 38891・NO ＝ 7937。`Qwen/Qwen3-1.7B` は YES ＝ 14004・NO ＝ 8996。チャットの型は各モデルのもの（`apply_chat_template`・`add_generation_prompt=True`。Qwen3 は `enable_thinking=False`）。どちらの型も、回答の位置の直前は改行で、最初のトークンは先頭の空白を持たない
- **プロンプト（全文。sha256 ＝ `d26a2c76734cb7911d01506e67f026a6c4bbaf846dab224c9a1b8c263afd4cec`。{ } を埋める前の文字列の UTF-8）:**

```
次の2つの文を読んで答えてください。
必要としている人の像: {必要像の文}
相手の自己紹介の文: {相手の文}
この自己紹介の文は、必要としている人の像の役割を満たしていますか。YES か NO の一語だけで答えてください。
```

- **モデル:** **`llm-jp/llm-jp-3-1.8b-instruct`**（Apache-2.0）revision `413b7929df092690b0f9449f3045baaf8deba0a5`・**fp32**・量子化なし。`Qwen/Qwen3-1.7B`（Apache-2.0）revision `70d244cc86ccca08cf5af4e1e306ecf908b1ad5e` は、**決定性を測る部分集合でだけ参考として**測る。記録: モデル id・revision・dtype・プロンプトのハッシュ・YES／NO の token id・チャットの型・スコアの取り方
- この作業環境（CPU 4・メモリ 15GB・GPU なし）では、4B 以上は fp32 でメモリに載らず、bf16 は fp32 の約 3 倍遅い。1.8B 級の fp32 で 1 対 約 1.4〜1.8 秒
- **単独性能:** **役割の 4 要素だけ**の全対で 1 回（約 12,100 対＝検証用 約 3000 文 × 4 要素 ＋ C 群 24 ＋ hard negative のうち役割の要素との対 ＋ 48 対のうち役割の要素と PA の必要像の対）
- **決定性:** 固定した部分集合（約 310 対）で 5 回。部分集合＝48 対のうち役割の要素と PA の必要像の対・hard negative のうち役割の要素との対・背景から無作為の 200 対（役割の 4 要素。seed 6603）。一致率を出す
- **費用:** 1 対あたりの時間
- **所見に必ず書くこと:** L の結論は **2B 級のモデルについてのもの**であり、L という方法そのものを否定するものではない
