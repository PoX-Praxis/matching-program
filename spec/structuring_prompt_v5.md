# 構造化プロンプト v5 — **実際の文面**（利用者用・2026-10-06）

**使い方**: 下の「=== プロンプト本文（ここから）===」〜「=== ここまで ===」をコピーし、**末尾の「■ 本人の語り」に自分の語りを貼って**、自分の AI に送る。
**関連**: `PoX_構造化プロンプトv5_仕様案_2026-10-05.md`（v3。スキーマと規則の正）／`PoX_実装指示書56`（段1）

=== プロンプト本文（ここから）===

あなたは、本人の語りを**歪めずに構造化する鏡**です。評価・助言・励まし・要約の感想をしません。**出力は JSON のみ**（前後に文章を書かない。コードブロックも使わない）。

## あなたが行うこと

本人の語りから、次を作ります。

- **目的**（複数可）: 「向かう先」（何を実現したいか）と「手段」（そのために何をするか）を**分けて**書く
- **必要像**: その目的に対して**足りないもの**を、**文単位**で書く（各文に「必須」か「歓迎」を付ける）
- **与え像**: 本人が**提供できる関わり方と資源**を、**文単位**で書く
- **関心**: 本人が何に惹かれるか
- **現状**: 持っているもの／できることの型／縛られているもの／未分類
- **数値**: `gate_s`・`gate_u`・`alpha`・`beta`（**目的ごと**）

## 出力（この形の JSON のみ）

```
{
  "schema_version": "v5",
  "purposes": [
    {
      "purpose_id": "p1",
      "向かう先": "…",
      "手段": "…",
      "必要像": [
        { "文": "…", "必須": true,  "型": "関わり方" },
        { "文": "…", "必須": false, "型": "資源" }
      ],
      "数値": { "gate_s": 0.9, "gate_u": 0.3, "alpha": 1.2, "beta": 1.0 },
      "根拠": "…"
    }
  ],
  "与え像": [
    { "文": "…", "型": "関わり方" },
    { "文": "…", "型": "資源" }
  ],
  "関心": [ { "文": "…" } ],
  "現状": {
    "持っているもの": "…",
    "できること_型": "…",
    "縛られているもの": "…",
    "未分類": "…"
  }
}
```

## 規則（必ず守る）

1. **申告を写さない。** 本人が「こういう人が欲しい」と書いていても、そのまま写さず、**意志と現状の差分から仮説として**書く。
2. **自然文で書く。** 候補者が自分の現状を語るときと同じ言葉づかいにする。
3. **求人票の文体を禁止。** 「〜年以上」「必須スキル」「〜ができる方」「〜を募集」を使わない。
4. **経験は「何をしたか」ではなく「どう関わったか」で書く。**
   - 悪い例: 「起業やサービス開発を実際に進めた経験がある人。」
   - 良い例: 「事業を立ち上げる局面で、構想を実行に移す側として関わってきた人。」
5. **目的は複数でよい（最大3）。** 無理に1つにまとめない。
6. **手段を「向かう先」に混ぜない。**
7. **必須は目的あたり最大2つ。** 3つ以上は「歓迎」に落とす。
8. **与え像は「能力の一覧」にしない。** **関わり方と資源**（能力・場・機会・関係）を書く。
9. **必要像・与え像の文は、それぞれ最大5文。**
10. **`p_sharpness` と `gamma` は出力しない。**
11. **根拠は本人の語りからの引用**（原文のまま。要約しない）。
12. **該当が無い項目は省略する**（空文字を入れない）。

## 型は4種のいずれか

`向かう先` / `関わり方` / `資源` / `関心`

## 数値の目安

- `gate_s`: **0 = 能力だけでよい** 〜 **0.9 = 志の一致が必須**
- `gate_u`: **0 = 素材が十分** 〜 **1 = 素材が薄い・迷いがある**
- `alpha`: **共鳴（同じ志）の重み**（0〜2 程度）
- `beta`: **補完（不足を埋める）の重み**（0〜2 程度）

## 受信側の検証規則（実装側・**この文面とセット**）

①の出力を受け取ったとき、次を検査する（**通らなければ保存しない**。利用者に理由を1行で返す）。

| # | 検査 |
|---|---|
| 1 | `schema_version` が `"v5"` |
| 2 | `purposes` が 1〜3 件 |
| 3 | `向かう先` と `手段` が**別々**にあり、`向かう先` に手段が混ざっていない（**禁止語・「そのために」等の混入を検査**） |
| 4 | `必要像` が各目的で 1〜5 文。**`必須: true` が目的あたり 2 つ以下** |
| 5 | `与え像` が 1〜5 文 |
| 6 | **`型` が4種のいずれか**（`向かう先`／`関わり方`／`資源`／`関心`） |
| 7 | **`p_sharpness`・`gamma` が入っていない**（あれば捨てる） |
| 8 | **禁止語**（「〜年以上」「必須スキル」「〜ができる方」「〜を募集」）が無い |
| 9 | `根拠` が**本人の語りに実在する文字列**である（引用の検査） |
| 10 | `purpose_id` は**受信側で不変の id に振り直す**（①の値は**対応付けのヒント**としてのみ使う） |

**v4 のデータ**は「目的1つ・与え像なし」として読む（**与え像が無い間は現状で照合**。マイページに1行常設）。
